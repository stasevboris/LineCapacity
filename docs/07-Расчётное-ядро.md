# Расчётное ядро

Расчётное ядро — пакет `linecapacity`. Оно находит установившийся режим
радиальной сети 0,4 кВ по схеме VoltPlan: напряжения у потребителей и на
шинах ТП, токи в каждом проводе, мощности, потери, температуры проводов и
трансформатора, износ изоляции трансформатора.

Ядро разработано для взаимозаменяемости с LineCapacity. Одна и та же схема
(файл `.cir`) даёт в обеих программах одинаковые числа: модель сети,
нормативные нагрузки и суточные графики, тепловые модели и правила вывода
чисел выбраны так, чтобы совпадали строки окна «Основные результаты расчётов»
и окон объектов. Единственное систематическое отличие текста — название
объекта при физически равных значениях: оно описано в разделе «Равные
значения». Совпадение проверяется автоматически (раздел «Проверка ядра»).

Ядро ничего не знает о сервере и интерфейсе VoltPlan. Сервер обращается к нему
через мост `voltplan.calc`: переводит единую структуру схемы в модель ядра,
вызывает расчёт и превращает результаты в строки и подписи для клиента.

## Состав пакета

| Модуль | Содержание |
|---|---|
| `model.py` | модель сети: `Transformer`, `Line`, `Pole`, `Consumer`, `ConnectionPoint`, `CircuitModel`; перечисления видов ЛЭП, фазности, вида нагрузки, вида потребителя, материала и изоляции; свойства марки провода (`Line.material`, `Line.insulation`, `Line.cores`, `Line.section_mm2`) и признак сухого трансформатора (`Transformer.is_dry`) |
| `constants.py` | нормативные и физические величины с говорящими именами: допустимые напряжения (`VOLTAGE_MIN`, `VOLTAGE_MAX`), типовые нагрузки (`HOME_SUMMER_KW`, `ELECTRIC_HOME_WINTER_KW` и т. д.), годовое потребление, температуры воздуха, теплофизические постоянные, пределы температур |
| `charts.py` | суточные графики типовой нагрузки по получасам: `HOME_SUMMER_CURVE`, `HOME_WINTER_CURVE` (бытовые без КИЭ), `ELECTRIC_HOME_SUMMER_CURVE`, `ELECTRIC_HOME_WINTER_CURVE` (с КИЭ) |
| `settings.py` | `CalculationSettings` — все настраиваемые величины расчёта со значениями по умолчанию из `constants.py` и `charts.py` |
| `solver.py` | расчёт: схема замещения, узловые уравнения, результаты по сезонам, тепловые расчёты, режим минимальных нагрузок |
| `allowed.py` | допустимая мощность потребителя по потерям напряжения и по перегрузке трансформатора |
| `meter.py` | распределение нагрузок потребителей по показаниям балансного прибора |

Главная функция:

```python
calculate(model: CircuitModel, settings: CalculationSettings,
          period: int = 2, min_load: bool = True) -> CalculationResults
```

`CircuitModel` содержит трансформатор, списки ЛЭП, опор, потребителей и точек
присоединения и число отходящих линий схемы `outgoing_count` — то же, что
строка 5 файла `.cir`. Номер отходящей линии у каждого объекта (`feeder_no`)
хранится отдельно и после удаления отходящей линии не пересчитывается.

`period`: 0 — летний период, 1 — зимний, 2 — оба; `min_load` — считать ли
режим минимальных нагрузок. Результат:

## Порядок расчёта

1. **Нумерация.** Каждому узлу и каждой ветви схемы замещения присваивается
   номер (класс `Layout`). Там же строятся словари «координаты → опора»,
   «начало ЛЭП → ЛЭП», «конец ЛЭП → ЛЭП», «ответвление опоры → точка
   присоединения», чтобы связность находилась за один проход.
2. **Соединения** (`Connections`): какой ветвью соединены какие узлы и в
   каком направлении.
3. **Дальние потребители** для утяжеления нагрузки.
4. **Для каждого сезона** (лето, зима — по выбору):
   1. сопротивления проводов при температуре воздуха сезона;
   2. сопротивления нагрузок потребителей;
   3. проводимости ветвей и ЭДС источника;
   4. решение узловых уравнений;
   5. напряжения потребителей, токи проводов, мощности;
   6. потери, шины ТП, распределение по фазам;
   7. тепловой расчёт проводов;
   8. график нагрузки и тепловой расчёт трансформатора.
5. **Режим минимальных нагрузок** — если он выбран и есть хотя бы один
   потребитель с типовой нагрузкой.

## Исходные данные объектов

### Трансформатор

Параметры схемы замещения трансформатора вычисляются при сохранении окна
трансформатора и хранятся в схеме и в файле `.cir`:

- активное сопротивление обмоток, приведённое к стороне НН:
  R = Pк · Uнн² / Sн²;
- полное сопротивление короткого замыкания: Z = Uк · Uнн² / (100 · Sн);
- индуктивное сопротивление: X = √(Z² − R²);
- коэффициент трансформации с учётом ступени ПБВ:
  Kт = (Uвн / Uнн) · (1 + n · ΔU / 100), где n — номер ступени, ΔU — процент
  одной ступени.

Величины берутся в основных единицах (Вт, В, ВА). Трансформатор считается
сухим, если в его марке есть «ТС»; у сухого трансформатора нет масла, и его
обмотки остывают и нагреваются быстрее.

### ЛЭП

Сопротивления ЛЭП в омах вычисляются при сохранении окна ЛЭП:

- трёхфазная: Rф = rф · L / 1000, Rн = rн · L / 1000, где rф, rн — погонные
  сопротивления фазного и нулевого провода, Ом/км, L — длина, м;
- однофазная: Rф = Rн = r · L / 1000, где r — погонное сопротивление провода.

Свойства провода, нужные тепловому расчёту, определяются по марке
(`Line` в `model.py`):

| Свойство | Правило |
|---|---|
| материал жил | алюминий, если в марке есть «А» (русская или латинская) или «СИП», иначе медь |
| изоляция | поливинилхлорид, если в марке есть «В»; сшитый полиэтилен, если есть «П»; иначе провод голый |
| число жил | сумма цифр, стоящих перед каждым знаком «x» (латинским или русским): «СИП-4 4х16» — 4, «3х50+1х54,6» — 4; если перед каким-либо знаком не цифра — 0; если знака нет — 4 для трёхфазной ЛЭП и 2 для однофазной; у марки из одного знака — 0 |
| сечение фазной жилы | число сразу после первого латинского «x»; если его нет — после первого русского «х»; если нет и его — после первого пробела; берётся до четырёх знаков из цифр и запятых, точка считается запятой («А 35» — 35 мм², «2х2.5» — 2,5 мм²) |

Как понята марка, видно в окне ЛЭП: там, как и в LineCapacity, всегда
выводятся четыре строки — «Материал провода», «Материал изоляции»,
«Количество жил», «Сечение фазного провода» (маршрут `GET /api/catalog/mark`).

Если в марке нет ни «x», ни «х», ни пробела, сечение считается равным 0 и в
тепловом расчёте заменяется на 16 мм². Если знак есть, а числа после него нет
(«СИП 4х») или оно не читается как число, сечение не определено: VoltPlan в
расчёте отказывает (раздел «Мост к серверу»).

### Потребители

Сопротивление нагрузки потребителя — параллельное соединение активного и
реактивного сопротивления, заданных при номинальном напряжении
Uном = 220 В:

- трёхфазный потребитель (на каждую фазу): R = 3 · Uном² / P, X = 3 · Uном² / Q;
- однофазный: R = Uном² / P, X = Uном² / Q;
- Q = P · tg φ, то есть Q = √(S² − P²), S = P / cos φ.

Нулевая мощность заменяется на 10⁻¹⁵ кВт, поэтому потребитель без нагрузки —
это практически разрыв цепи, а не деление на ноль.

Мощность P берётся так.

**Индивидуальная нагрузка** — мощность и cos φ из окна потребителя.

**Типовая нагрузка** — по виду потребителя и сезону, пропорционально
годовому потреблению W:

| Вид потребителя | Лето, кВт | Зима, кВт | Мин. нагрузки, кВт | Годовое потребление типового потребителя |
|---|---|---|---|---|
| бытовой без КИЭ | 0,31 · W / 1293 | 0,35 · W / 1293 | 0,08 · W / 1293 | 1293 кВт·ч |
| бытовой с КИЭ | 0,85 · W / 8507 | 4,15 · W / 8507 | 0,1 · W / 8507 | 8507 кВт·ч |
| уличное освещение | 0,82 · W / 577 | 0,83 · W / 577 | ≈ 0 | 577 кВт·ч |
| иной | W / 8760 | W / 8760 | ≈ 0 | — |

cos φ типовых нагрузок — 0,998. Если в файле вид потребителя не равен 0…3
(в файлах встречаются значения вроде 49,894), типовая нагрузка ему не
назначается и потребитель тока не потребляет.

**Утяжеление.** Летом и зимой к нагрузке самого дальнего однофазного
потребителя с типовой нагрузкой каждой фазы на каждой отходящей линии
добавляется 2,6 кВт. Дальний — с наибольшей координатой x; при равенстве —
встретившийся первым. Если на отходящей линии нет однофазного потребителя с
типовой нагрузкой какой-то фазы, дальним для этой фазы на этой линии
считается первый потребитель схемы (номер 0).

Дальние потребители ищутся на отходящих линиях с номерами 0 … N − 1, где N —
число отходящих линий схемы (`outgoing_count`). Обычно номера объектов идут
подряд с нуля, и так перебираются все линии. Но если удалить не последнюю
отходящую линию, N уменьшается, а номера оставшихся объектов прежние: например,
после удаления первой из двух линий N = 1, а у оставшихся объектов номер 1.
Тогда на этой линии дальних потребителей не ищут, утяжеления нет (Pут = 0) и
строка об утяжелении не выводится — так же считает LineCapacity. Случай
проверяется сценарием «удаление-первой-отходящей» (раздел «Проверка ядра»).

Добавка получает потребитель, если он назначен дальним хотя бы для одной фазы
на своей отходящей линии, у него типовая нагрузка и он бытовой без КИЭ; каждому
— не больше одного раза. Первый потребитель схемы получает добавку по
умолчанию, только если он сам стоит на отходящей линии, где для какой-то фазы
однофазного потребителя с типовой нагрузкой нет, и сам удовлетворяет этим
условиям; назначения на других отходящих линиях его не касаются.

Строка «Потребителю добавлена мощность утяжеления!» выводится в окне
однофазного потребителя, назначенного дальним на своей фазе и своей
отходящей линии, — в том числе первого потребителя схемы, назначенного по
умолчанию, — даже если по виду или виду нагрузки добавка ему не положена
(освещение, индивидуальная нагрузка). Так же выводит её LineCapacity.

## Схема замещения

### Узлы

| Узлы | Число | Что это |
|---|---|---|
| шины ТП | 3 | фазы L1, L2, L3 на стороне НН |
| опора | 4 на опору | фазы L1, L2, L3 и нулевой провод в точке опоры |
| трёхфазный потребитель | 4 | фазы и нулевой провод на вводе |
| однофазный потребитель | 2 | фазный и нулевой провод на вводе |

Опорный узел (потенциал 0) — нейтраль трансформатора.

### Ветви

| Ветви | Число | Проводимость |
|---|---|---|
| трансформатор | 3 | y = 1 / (R + jX), в каждой ветви — ЭДС своей фазы |
| ЛЭП | 4 на ЛЭП: три фазных и нулевой провод | y = 1 / Rпр |
| однофазное ответвление к потребителю | 2: фазный и нулевой провод | y = 1 / Rпр |
| трёхфазный потребитель | 3: нагрузки фаза — нуль | y = 1/R − j/X |
| однофазный потребитель | 1 | y = 1/R − j/X |

Однофазная ЛЭП, которая не является ответвлением к потребителю (пролёт,
ответвление к другой линии, отходящая линия), моделируется четырьмя
проводами, как трёхфазная: у всех проводов сопротивление Rф. Нулевой провод
отходящей ЛЭП соединяет нуль первой опоры с нейтралью трансформатора.

Нулевые сопротивления заменяются на 10⁻⁹ Ом.

### Сопротивление провода при температуре воздуха

Rпр = R · (1 + α · (tв + 5 − tб)) + Rк, где:

- R — сопротивление провода из окна ЛЭП (Rф или Rн);
- α = 0,0042 1/°C;
- tв — расчётная температура воздуха для ЛЭП: 32,3 °C летом, 20,5 °C зимой;
  5 °C — добавка на нагрев провода;
- tб — температура, при которой задано сопротивление: 20 °C для голого
  провода, 25 °C для изолированного;
- Rк = 0,001 Ом — сопротивление контактов, только у ответвлений (к другой
  линии и к потребителю).

### Связность

Связность читается по координатам, как в файле `.cir`:

- ЛЭП, конец которой совпадает с началом опоры, питает эту опору: четыре её
  провода соединяют узлы предыдущей опоры (или шин ТП) с узлами этой опоры;
- ЛЭП, начало которой совпадает с концом опоры, продолжает линию от неё;
- ответвление № i опоры находится по точке присоединения опоры с номером
  ответвления i; ЛЭП, начинающаяся в этой точке, подключается к узлам опоры.
  Однофазное ответвление к потребителю подключается к узлу своей фазы и к
  нулю опоры;
- потребитель подключён к ЛЭП, конец которой совпадает с его положением.

Если объектов с одинаковыми координатами несколько, берётся первый в списке.

### Узловые уравнения

Схема описывается матрицей соединений A: строка — узел, столбец — ветвь,
элемент +1 или −1 показывает, в какой узел ветвь входит и из какого выходит.
Проводимости ветвей образуют диагональную матрицу Y_в, ЭДС — вектор E.
Потенциалы узлов φ находятся из системы

  Y · φ = J,  Y = A · Y_в · Aᵀ,  J = −A · Y_в · E.

ЭДС есть только в ветвях трансформатора:

  E₁ = Uф, E₂ = Uф · e^(−j120°), E₃ = Uф · e^(j120°),  Uф = Uвн · 10³ / (Kт · √3),

где Uвн = 10 кВ — номинальное напряжение сети ВН. При Kт = 25 фазная ЭДС
равна 230,9 В.

Матрица Y собирается сразу в разреженном виде: каждая ветвь добавляет
произведения своих коэффициентов только в клетки своих узлов. Система
решается LU-разложением разреженной матрицы (SciPy). Схемы, которые дали бы
вырожденную матрицу (потребитель или опора вне ЛЭП, ЛЭП не с опоры),
отклоняются до расчёта (раздел «Мост к серверу»). Если матрица всё же
окажется вырожденной, решение ищется плотным методом, а при полной
вырожденности — методом наименьших квадратов.

## Результаты режима

**Напряжение у потребителя** — разность потенциалов фазного и нулевого узла
на вводе: U = |φф − φн|. У трёхфазного — по трём фазам, у однофазного — по
своей фазе.

**Ток провода** — I = (φначала − φконца) / Rпр. Ток нулевого провода
отходящей ЛЭП — потенциал нуля первой опоры, делённый на сопротивление
провода. В окне ЛЭП токи меньше 0,001 А показываются как 0,000. У трёхфазной
ЛЭП окно показывает токи трёх фаз и нуля; у однофазной — токи первых двух
проводов модели: у ответвления к потребителю это фазный и нулевой провод.

**Мощности потребителя** — P = Σ U² / R, Q = Σ U² / X по его фазам.

**Шины ТП:** напряжения фаз U₁…U₃ — потенциалы узлов шин; мощности фаз —
Sф = Σ Uф · Iф* по отходящим линиям. Pсум и Qсум — суммы по фазам. Как и при
утяжелении, число отходящих линий берётся из схемы (`outgoing_count`, строка 5
файла `.cir`): суммируются первые N отходящих ЛЭП в порядке их следования в
схеме. У схемы, построенной в VoltPlan или LineCapacity, N равно числу
отходящих ЛЭП; расходятся они только у вручную исправленного файла, и тогда
VoltPlan, как и LineCapacity, считает по строке 5.

**Потери мощности в ЛЭП:** ΔP = Pсум − ΣPпотр; в процентах —
ΔP / Pсум · 100 (при Pсум ≤ 0,01 Вт — 0).

**Наименьшее напряжение у потребителя** ищется по всем фазам всех
потребителей. **Потери напряжения** — относительное снижение от шин ТП до
этого потребителя: ΔU = (|Uшин| − Uмин) / |Uшин| · 100 %, где Uшин —
напряжение шины той фазы, на которой получен минимум. Поиск начинается со
значения 400 В у потребителя № 0 и фазы L1; если найденный потребитель
однофазный, берётся фаза, к которой он подключён. Поэтому при заведомо
неверных данных, когда ни одно напряжение не ниже 400 В, потери считаются
по фазе потребителя № 0 (если он однофазный) — так же, как в LineCapacity.

**Распределение мощности по фазам** — Pф / Pсум · 100 % (отрицательное — 0).
Если мощность на шинах не больше 0,01 Вт (все нагрузки нулевые), доли равны 0.

**Мощность нагрузки трансформатора** — S = √((Pсум − Pут)² + Qсум²), где
Pут — мощность утяжеления.

### Равные значения

Если наибольшее или наименьшее значение достигается у нескольких объектов
(разница меньше 10⁻⁹), VoltPlan называет первый из них.

Такие совпадения в реальных сетях часты. Температура провода не зависит от
длины пролёта: тепло, выделяемое током, и поверхность охлаждения растут с
длиной одинаково. Поэтому все пролёты одной марки подряд, по которым идёт один
и тот же ток, нагреты одинаково. Так же одинаковы напряжения у потребителей,
стоящих на одном ответвлении без нагрузки между ними. Вычисленные значения
таких объектов отличаются лишь ошибками округления, порядка 10⁻¹³.

LineCapacity в этом случае называет тот объект, у которого значение оказалось
больше или меньше на эти ошибки округления. Повторить её выбор нельзя: он
зависит от порядка операций её решателя. Поэтому в тексте «Основных
результатов» название самой нагретой ЛЭП, потребителя с наименьшим или
наибольшим напряжением может отличаться от LineCapacity, а число в следующей
строке — одно и то же. Среди 18 образцов так бывает в шести:

| Образец | LineCapacity | VoltPlan |
|---|---|---|
| Гатское КТП179, зима | ЛЭП между опорами №2 и №3 | ЛЭП между опорами №1 и №2 |
| Ковалёв Рог МТП №66 | ЛЭП между опорами №3 и №4 | ЛЭП между опорами №2 и №3 |
| Новозахарполье КТП404 | ЛЭП между опорами №2 и №3 | ЛЭП между опорами №1 и №2 |
| Р.Бартоломеевская КТП №282 | ЛЭП между опорами №3 и №4 (лето), №2 и №3 (зима) | ЛЭП между опорами №1 и №2 |
| Р.Нисимковичская КТП178 | ЛЭП между опорами №4 и №5 | ЛЭП между ТП и опорой №1 |
| Сидоровичи МТП374, зима | потребитель ул. Вишневая, д.11 | потребитель ул. Вишневая, д.12 |

Все такие случаи записаны в проверочных данных вместе с причиной, и проверки
падают, если появится расхождение, которого там нет (раздел «Проверка
ядра»).

## Тепловой расчёт провода

Температура провода рассчитывается по установившемуся тепловому балансу:
тепло, выделяемое током, отводится через изоляцию и с поверхности излучением
и конвекцией. Расчёт ведётся по току первого провода ЛЭП (фаза L1; у
однофазного ответвления к потребителю — фазный провод).

**Геометрия.** Сечение S → диаметр жилы d₁ = √(4S / π). У голого провода
наружный диаметр d₂ = d₁. У изолированного d₂ = d₁ + 2 · 1,5 мм.

**Доля охлаждаемой поверхности жилы** kохл (`COOLING_BY_CORES`). В проводе из
нескольких жил, скрученных в жгут (СИП, кабель), каждая жила касается
соседних, и часть её окружности обращена не наружу, а к другим жилам, которые
нагреты так же. Тепло уходит в окружающий воздух только через обращённую
наружу часть поверхности. Её угловую долю и учитывает коэффициент: 1 жила —
вся окружность, kохл = 1; 2 жилы — 260° из 360°; 3 жилы — 240° из 360°;
4 и больше — 230° из 360°. Чем больше жил, тем меньше свободная доля и тем
горячее провод при том же токе.

**Тепловое сопротивление изоляции:**

  Rиз = ln(d₂ / d₁) / (kохл · 2π · λ · L),

λ = 0,29 Вт/(м·°C) для сшитого полиэтилена, 0,2 — для ПВХ; у голого провода
Rиз = 0.

**Поверхность охлаждения:** F = kохл · π · d₂ · L.

**Итерации** (пять шагов, начиная с t₁ = t₂ = tв и α = 10 Вт/(м²·°C)):

1. выделяемая мощность P = I² · R · (1 + αм · (t₁ − tб)), αм = 0,0042 для
   алюминия и 0,0043 для меди, tб — 20 или 25 °C;
2. тепловое сопротивление поверхности Rп = 1 / (α · F);
3. температура жилы t₁ = P · (Rиз + Rп) + tв; температура поверхности
   t₂ = t₁ у голого провода и t₂ = P · Rп + tв у изолированного;
4. коэффициент теплоотдачи: если t₂ − tв < 0,1 — α = 10; иначе
   α = αизл + αконв:
   - излучение αизл = ε · σ · ((t₂ + 273)⁴ − (tв + 273)⁴) / (t₂ − tв),
     ε = 1, σ = 5,67037·10⁻⁸ Вт/(м²·К⁴);
   - конвекция αконв = 0,0749 · √(p / (tв + 273)) · ((t₂ − tв) / d₂)^0,25,
     p = 10⁵ Па.

Результат — t₁. Допустимая температура: 70 °C для голого провода и ПВХ,
90 °C для сшитого полиэтилена. Без тока температура провода равна
температуре воздуха.

Значения не ограничиваются: при сильной перегрузке температура может
достигать десятков тысяч и миллиардов градусов (например, 1,04E4 и
5,425E10 °C) — эти числа выводятся так же, как в LineCapacity. Если значение
выходит за пределы вещественных чисел, выводится INF.

## Тепловой расчёт трансформатора

**Суточный график нагрузки.** Доля мощности бытовых потребителей с КИЭ

  kp = ΣPс КИЭ / (Pсум − Pут)

(вне 0…1 — 0) смешивает типовые графики сезона (48 получасов):

  g(i) = (1 − kp) · gбез(i) / Pбез + kp · gс(i) / Pс,

где Pбез и Pс — типовые нагрузки сезона (0,31 и 0,85 кВт летом, 0,35 и
4,15 кВт зимой): каждый график делится на свой максимум. Затем график
масштабируется так, чтобы его наибольшее значение равнялось мощности
нагрузки трансформатора:

  S(i) = S · g(i) / max g,  K(i) = S(i) / Sн — коэффициент загрузки.

**Температура масла** — экспоненциальная модель с шагом Δt = 30 мин и
постоянной времени τ = 3 ч (у сухого трансформатора — 1 ч):

  θуст(i) = 60 · ((1 + d · K(i)²) / (1 + d))^0,9,  d = Pк / Pхх;
  Δθ(i) = θуст(i) + (Δθ(i − 1) − θуст(i)) · e^(−Δt/τ).

Расчёт начинается с Δθ = 0 и проходит двое суток подряд; результат —
вторые сутки. Температура масла θм(i) = tв,тр + Δθ(i), температура обмоток
θо(i) = θм(i) + 23 · K(i)^1,6. Температура воздуха для трансформатора —
21,9 °C летом и 8,9 °C зимой.

**Суточный износ изоляции:**

  V = (24 / 48) · Σ 2^((θо(i) − 98) / 6), ч.

**Состояние трансформатора:**

| Условие | Сообщение |
|---|---|
| масло > 115 °C или обмотки > 140 °C | «Внимание! Недопустимая температура трансформатора!» |
| масло > 95 °C или обмотки > 98 °C, износ < 24 ч | «Трансформатор работает с кратковременной (допустимой) перегрузкой!» |
| масло > 95 °C или обмотки > 98 °C, износ ≥ 24 ч | «Внимание! Трансформатор работает с длительной перегрузкой!» |
| иначе | «Трансформатор работает без перегрузки!» |

Графики K(i), θо(i), θм(i) показываются в окне трансформатора по вкладкам
«Летний период» и «Зимний период».

## Режим минимальных нагрузок

Считается один раз, если он выбран и в схеме есть потребитель с типовой
нагрузкой:

- типовые нагрузки — минимальные (0,08 и 0,1 кВт на типового потребителя
  без КИЭ и с КИЭ, освещение и иные — практически 0);
- потребители с индивидуальной нагрузкой отключены;
- утяжеления нет;
- сопротивления проводов пересчитываются к температуре воздуха 21,9 °C.

Результат — наибольшее напряжение у потребителя (у трёхфазного — наибольшее
из трёх фаз) и напряжения всех потребителей в этом режиме.

## Заключение о пропускной способности

Заключение составляет мост `voltplan.calc.results` по результатам ядра. Оно
«недостаточна», если хотя бы в одном рассчитанном сезоне:

- потери напряжения на ЛЭП не меньше 8 %;
- температура самого нагретого провода выше допустимой для его изоляции;
- температура трансформатора недопустима или он работает с длительной
  перегрузкой.

Напряжение у потребителя на заключение не влияет. Предупреждение в отчёте
выводится, если наименьшее напряжение не выше 198 В (≤ 198 В) или
наибольшее не ниже 242 В (≥ 242 В). Подпись напряжения на схеме — у
потребителя и на шинах ТП — красная, если напряжение строго меньше 198 В или
строго больше 242 В; значение 198,0 В даёт предупреждение в отчёте, но
подпись остаётся зелёной. Так же в LineCapacity. Подпись температуры ЛЭП
красная, если температура строго выше допустимой для изоляции провода.

## Вывод чисел

Все числа в окнах и подписях выводит сервер, по тем же правилам, что
LineCapacity (`voltplan/calc/text.py`).

**Фиксированный формат** с точностью p значащих цифр и d знаками после
запятой:

1. число берётся с 18 значащими цифрами;
2. округляется до p значащих цифр (половина — от нуля);
3. если целая часть после округления длиннее p цифр, число пишется с
   порядком: мантисса из p значащих цифр без хвостовых нулей, «E», порядок
   без знака «+» — `2,12824E8`, `1E4`;
4. иначе после запятой пишется d знаков; цифры сверх p значащих — нули:
   9999,44 при p = 4, d = 1 — `9999,0`.

**Общий формат** (подписи напряжений на схеме) — до p значащих цифр без
хвостовых нулей; с порядком, если целая часть длиннее p цифр или число
меньше 10⁻⁴: `230`, `210,5`, `1E-5`.

Бесконечность и неопределённость пишутся как `INF`, `-INF`, `NAN`. Дробный
разделитель — запятая.

| Величина | Формат |
|---|---|
| напряжения в отчёте и в окнах, температуры | фиксированный, p = 4, d = 1 |
| потери напряжения, % | фиксированный, p = 4, d = 1 |
| распределение активной мощности по фазам, % | фиксированный, p = 4, d = 1 |
| токи | фиксированный, p = 5, d = 3 |
| мощности, кВт и квар | фиксированный, p = 5, d = 2 |
| потери мощности, % | фиксированный, p = 4, d = 2 |
| коэффициент загрузки | фиксированный, p = 4, d = 2 |
| износ изоляции | фиксированный, p = 6, d = 2 |
| подписи напряжений у потребителей | общий, p = 4 |

Напряжение потребителя меньше 0,1 В в окне показывается как 0,0.

## Мост к серверу

`voltplan.calc.bridge.to_model` переводит единую структуру схемы в модель
ядра без потерь: каждое поле трансформатора, ЛЭП, опоры, потребителя и точки
присоединения переносится как есть, коды видов превращаются в перечисления.

`voltplan.calc.results.run` проверяет схему, вызывает ядро и собирает ответ
`POST /api/calc` (см. «Архитектура»): числа по сезонам, подписи на схеме,
строки окон объектов, графики трансформатора, текст отчёта. Расчёт не
запускается, если:

| Условие | Сообщение |
|---|---|
| у ЛЭП свободный конец | «В схеме имеются неприсоединённые ЛЭП! Расчёт не запущен!» |
| нет потребителей | «В схеме отсутствуют потребители! Расчёт не запущен!» |
| нет ЛЭП | «В схеме отсутствуют ЛЭП! Расчёт не запущен!» |
| есть ЛЭП нулевой длины | «В схеме имеются ЛЭП нулевой длины! Расчёт не запущен!» |
| потребитель стоит не в конце ЛЭП | «В схеме имеются потребители, не присоединённые к ЛЭП! Расчёт не запущен!» |
| опора стоит не в конце ЛЭП | «В схеме имеются опоры без питающей ЛЭП! Расчёт не запущен!» |
| ЛЭП (кроме отходящей) начинается не на опоре | «ЛЭП «…» не начинается на опоре! Расчёт не запущен!» |
| в марке провода есть «x», «х» или пробел, но сечение не читается | «В марке провода «…» ЛЭП «…» нет сечения жилы! Расчёт не запущен!» |
| у потребителя с индивидуальной нагрузкой cos φ ≤ 0 | «У потребителя «…» с индивидуальной нагрузкой cos φ не больше нуля! Расчёт не запущен!» |

Первые два сообщения совпадают с LineCapacity. Остальные случаи можно
получить только из файла или вводом заведомо неверных данных; окно
потребителя не принимает cos φ ≤ 0 для индивидуальной нагрузки.

## Настройки расчёта

Все величины расчёта собраны в `CalculationSettings` (`settings.py`). На
сайте они приходят из трёх слоёв, каждый следующий уточняет предыдущий:

1. **справочник типовых нагрузок** — общий для всех, правит администратор;
   исходные значения — `constants.py` и `charts.py`;
2. **настройки проекта** — сохраняются вместе с проектом;
3. **сценарий** — набор изменённых величин одного сценария расчёта.

Сервер собирает слои функцией `voltplan.calc.settings.build` и проверяет их
так же, как окно «Настройки расчёта» LineCapacity: cos φ — от −1 до 1 (и не 0:
при cos φ = 0 полная мощность не определена), номинальное, наименьшее и
наибольшее напряжения, линейное напряжение ВН, типовые мощности освещения и
бытовых потребителей, годовые потребления — больше нуля, сопротивление
контактов — не меньше нуля. Ошибка — «Неверные данные! Повторите ввод!».
Окно LineCapacity пропускает и бессмысленные величины; VoltPlan дополнительно
отказывает в них с понятным текстом, потому что настройки хранятся в проекте и
участвуют в сравнении вариантов: любая величина по модулю не больше 1 000 000;
наименьшее допустимое напряжение меньше номинального, номинальное меньше
наибольшего; допустимые потери напряжения больше 0 и меньше 100 %; мощность
утяжеления и минимальные нагрузки не отрицательны. Для настроек, которые
LineCapacity принимает в окне, это расхождение не проявляется на расчёте
правильно заданной схемы.

| Величина окна | Поле `CalculationSettings` | Где используется |
|---|---|---|
| температура воздуха для проводов, лето / зима | `line_air_summer`, `line_air_winter` | сопротивление и нагрев проводов |
| температура воздуха для трансформатора, лето / зима | `transformer_air_summer`, `transformer_air_winter` | нагрев трансформатора |
| номинальное напряжение у потребителя | `voltage_rated` | сопротивления нагрузок |
| наибольшее и наименьшее допустимое напряжение | `voltage_max`, `voltage_min` | предупреждения, красные подписи |
| линейное напряжение ВН | `high_voltage_kv` | ЭДС источника |
| допустимые потери напряжения | `voltage_loss_limit` | заключение, допустимая мощность |
| сопротивление контактов | `contact_resistance_ohm` | ответвления от опор |
| мощности и cos φ бытовых без КИЭ, с КИЭ, освещения по сезонам; минимальные мощности | `home_*`, `electric_home_*`, `street_light_*` | типовые нагрузки |
| мощность утяжеления, признак утяжеления | `extra_load_kw`, `extra_load_enabled` | утяжеление |
| типовое годовое потребление, учёт годового потребления | `*_annual_kwh`, `scale_by_annual` | масштаб типовых нагрузок |
| суточные графики по получасам | `*_curve` | график нагрузки трансформатора |

В окне LineCapacity есть ещё поля «cos φ минимальной нагрузки». Они показывают
и меняют cos φ **летней** нагрузки, а в режиме минимальных нагрузок берётся
cos φ **зимней** (таблица в разделе «Потребители»). Чтобы не вводить
пользователя в заблуждение, в VoltPlan этих повторяющих полей нет; cos φ
режима минимальных нагрузок — это cos φ зимней нагрузки.

«Присвоить всем потребителям типовые значения нагрузки» в LineCapacity
заодно возвращает температуры воздуха для проводов к исходным значениям.
VoltPlan делает то же на сервере (`voltplan.calc.tools.settings_after_load_kind`):
из настроек убираются изменённые температуры воздуха для проводов, и новые
настройки сохраняются в проект. Исходное значение в VoltPlan — значение
справочника типовых нагрузок; пока администратор его не менял, оно равно
исходному значению LineCapacity (32,3 °C летом и 20,5 °C зимой).

## Допустимая мощность потребителя

Модуль `allowed.py`, функция `allowed_power`. Отвечает на вопрос: какую
активную мощность можно отдать потребителю, чтобы потери напряжения не
превысили допустимых и трансформатор не перегрузился. Доступна после расчёта
по двум периодам, если пропускная способность сети достаточна (в LineCapacity
кнопка окна потребителя доступна при тех же условиях).

**Сезон.** Берётся сезон, в котором расчётная мощность этого потребителя
больше; при равенстве — зимний.

**Шаг 1 — исходный режим.** По сопротивлению нагрузки потребителя R в этом
сезоне (без утяжеления) находится исходная мощность
P₁ = 220² / R. У однофазного потребителя это его мощность, у трёхфазного —
мощность одной фазы (R трёхфазной нагрузки втрое больше). Далее запоминаются:

- фаза k: у однофазного — его фаза, у трёхфазного — фаза с наименьшим
  напряжением (первая из равных);
- U₁ — напряжение потребителя на фазе k;
- U₁ₘᵢₙ — наименьшее напряжение в сети (у потребителя с наименьшим
  напряжением: у трёхфазного — наименьшее из фаз, у однофазного — на его фазе);
- потребитель на той же отходящей линии с наименьшим напряжением на фазе k
  (трёхфазные — все, однофазные — только с той же фазой, что записана у
  выбранного потребителя) и его напряжение U₁ₗ;
- допустимый уровень Uдоп₁ = |U шин, фаза k| · (1 − ΔUдоп / 100), ΔUдоп — 8 %.

**Шаг 2 — утяжелённый режим.** Потребитель получает индивидуальную нагрузку
P₂ = P₁ + 5 кВт с прежним cos φ, схема рассчитывается по двум периодам без
режима минимальных нагрузок. Те же величины (U₂, U₂ₘᵢₙ по новому наименьшему,
U₂ₗ того же потребителя линии, Uдоп₂) снимаются в том же сезоне.

**Кандидаты по напряжению** — линейная экстраполяция запаса напряжения до нуля:

  Pᵢ = P₁ + (U₁ − Uдоп₁) · (P₂ − P₁) / ((U₁ − Uдоп₁) − (U₂ − Uдоп₂))

для самого потребителя, для потребителя с наименьшим напряжением в сети и для
потребителя с наименьшим напряжением на его линии.

**Кандидаты по трансформатору** — для каждого сезона суточный график
коэффициента загрузки шага 1 умножается на 1,05, пока расчётная температура
масла не достигнет 95 °C или обмоток — 98 °C (длительно допустимые). Прирост
наибольшего коэффициента загрузки Δk переводится в активную мощность:
Pₜ = Δk · Sн · 1000 · cos(arctg(Q / P)), где P — суммарная активная мощность
этого сезона, а Q — суммарная реактивная мощность **зимнего** сезона (так же
делает LineCapacity).

**Ответ.** По потерям напряжения — наименьший положительный из трёх
кандидатов, по перегрузке трансформатора — наименьший положительный из двух
(значения от 10⁹ Вт не учитываются). Если по трансформатору положительного нет
или знаменатель экстраполяции равен нулю — «Расчёт выполняется некорректно!
Проверьте данные по нагрузкам!». Результат выводится окном «Допустимая
мощность потребителя по адресу …» и четырьмя строками в окне потребителя.

Расхождения с LineCapacity: после этого расчёта LineCapacity оставляет на
схеме результаты утяжелённого режима (со +5 кВт), а VoltPlan — исходного;
если в LineCapacity график нагрузки трансформатора не растёт (нулевая нагрузка),
её цикл не заканчивается, VoltPlan прекращает его через 5000 шагов с тем же
сообщением об ошибке.

## Распределение нагрузок по балансному прибору

Модуль `meter.py`, функция `spread_by_meter`. Пользователь вводит показания
балансного прибора на шинах ТП — активную P и реактивную Q мощности — и месяц.
Май–сентябрь — летний период, остальные — зимний. Для периода берутся
типовые мощности бытовых без КИЭ, с КИЭ и освещения.

Расчётная мощность сети

  Pᵣ = Pбез · k₁ + Pс · k₂ + Pосв · k₃ + Wиных / 8760,

где k₁, k₂, k₃ — суммы Wᵢ / Wтип по потребителям каждого вида, если учитывается
годовое потребление, иначе — число потребителей этого вида; Wиных — суммарное
годовое потребление потребителей вида «иной». Коэффициент c = P / Pᵣ. Каждый
потребитель получает индивидуальную нагрузку: бытовой и освещение —
Pтип · c · (Wᵢ / Wтип) (или Pтип · c без учёта годового потребления), иной —
Wиных / (8760 · nиных) · c; у всех cos φ = cos(arctg(Q / P)). Сумма назначенных
мощностей равна показанию прибора. Следующий запуск расчёта предлагает
период, соответствующий месяцу. При P = 0 или нулевой расчётной мощности —
«Некорректные данные! Повторите ввод!» (LineCapacity в этом случае успевает
изменить первого потребителя; VoltPlan схему не меняет).

## Импорт нагрузок из файла Excel

Модуль `voltplan/exchange/meters.py`. Файл — выгрузка системы учёта
(АСКУЭ) в формате, который читает LineCapacity (первый лист книги `.xlsx`):

- строка 8, начиная со столбца H, — даты и время получасовых интервалов;
  чтение идёт вправо до ячейки короче трёх знаков;
- столбец B, начиная со строки 11, — адреса приборов учёта; чтение идёт вниз
  до пустой ячейки;
- на пересечении — энергия за получас, кВт·ч.

Пользователь выбирает интервал, cos φ (по умолчанию 1,0) и температуру
воздуха (по умолчанию 0,0 °C). Адрес прибора потребителя берётся из его
дополнительных данных: текст после первых 21 знака (длина фразы «Адрес
прибора АСКУЭ: ») до первой запятой, не больше 16 знаков. Три случая:

- текст не длиннее 21 знака — адреса нет (0);
- после 21 знака идут 16 знаков без запятой — адреса тоже нет (0);
- текст длиннее 21 знака, но заканчивается раньше, чем встретится запятая
  (например, стандартное «мощность по ТУ: 3,5 кВт» или «Адрес прибора
  АСКУЭ: 8476»), — адрес не читается, импорт отклоняется «Импорт прерван…».

Для каждой строки
таблицы первый потребитель с тем же адресом получает индивидуальную нагрузку
P = энергия / 0,5 ч и выбранный cos φ; ноль даёт 10⁻¹⁵ кВт. Если ячейка пуста или в ней текст, который не
читается как число с десятичной запятой (например, «0.75» с точкой), потребитель получает 10⁻¹⁵ кВт, а cos φ
у него не меняется.
Месяц интервала (два знака после первой точки даты) определяет период;
температура воздуха для проводов этого периода становится равной введённой
(`settings_after_import`; для проекта новые настройки сохраняются в нём).
Итог — «Найдены нагрузки для n потребителей из N потребителей в схеме».
Если адрес в таблице — не целое число, выводится сообщение «Некорректное
значение адреса прибора АСКУЭ в строке №: m», но строка всё равно
обрабатывается — с адресом из предыдущей строки (для первой строки — 0), и
только после неё чтение таблицы прекращается: так ведёт себя LineCapacity, и
значение из неверной строки достаётся потребителю с прежним адресом. Если
адрес не читается у потребителя — «Некорректно читается адрес прибора
АСКУЭ!», и дальше совпадения не ищутся.
LineCapacity открывает книгу через Microsoft Excel; VoltPlan читает `.xlsx`
сам и Excel не требует.

## Качество напряжения по ГОСТ 32144-2013

Функция `voltplan.calc.compare.gost_quality`. Установившееся отклонение
напряжения δU = (U − Uном) / Uном · 100 % в точке передачи электроэнергии не
должно выходить за ±10 % номинального значения (п. 4.2.2 ГОСТ 32144-2013).
Uном — номинальное напряжение у потребителя из настроек (220 В). Проверяются
все рассчитанные сезоны и режим минимальных нагрузок, у трёхфазного
потребителя — все фазы, у однофазного — его фаза. Для каждого потребителя
выводятся наименьшее и наибольшее отклонение и вывод «в норме» / «вне нормы».

## Сравнение вариантов

Модуль `voltplan.calc.compare`. Каждый вариант проекта рассчитывается с
одними и теми же настройками. Показатели варианта берутся по худшему сезону:
наименьшее напряжение у потребителя, наибольшие потери напряжения, потери
мощности в ЛЭП, температура провода, коэффициент загрузки и износ изоляции
трансформатора; для тарифа «Максимум» — годовые потери энергии и их стоимость.

Лучший вариант выбирается по порядку:

1. пропускная способность сети достаточна;
2. напряжение у всех потребителей в пределах ±10 % (ГОСТ 32144-2013);
3. выше наименьшее напряжение у потребителя;
4. ниже потери мощности в ЛЭП.

Лучшие значения каждого показателя выделяются: наибольшее из наименьших
напряжений, наименьшие из остальных величин.

## Эпюра напряжения

Модуль `voltplan.calc.profile`. Путь строится от потребителя к шинам ТП:
ЛЭП, которая заканчивается у потребителя, → опора, от которой она начинается,
→ ЛЭП, которая заканчивается у начала этой опоры, и так до отходящей линии.
Для шин берутся напряжения шин, для опоры — фазные напряжения её узла
(потенциал фазного провода относительно нулевого), для потребителя — его
напряжения. По оси абсцисс — расстояние от шин по длинам ЛЭП.

## Годовые потери энергии

Модуль `voltplan.calc.losses`. Потери оцениваются методом времени наибольших
потерь. Tmax — время использования наибольшей нагрузки: годовое потребление
всех потребителей, делённое на наибольшую активную нагрузку сети (без
утяжеления); если потребление не задано, Tmax = 3000 ч.

  τ = (0,124 + Tmax / 10 000)² · 8760 ч,
  ΔWлэп = ΔPлэп,max · τ,  ΔWтр = Pхх · 8760 + Pкз · β²ₘₐₓ · τ,

где ΔPлэп,max — наибольшие потери мощности в ЛЭП по сезонам, βₘₐₓ —
наибольший коэффициент загрузки трансформатора. Стоимость — ΔW, умноженное на
стоимость электроэнергии, которую задаёт администратор (по умолчанию
0,08 $ за кВт·ч).

Если наибольшая нагрузка сети (без утяжеления) получилась не больше нуля —
например, при неверно заданном напряжении на стороне ВН, — Tmax не имеет смысла,
и годовые потери не рассчитываются: выводится отказ с пояснением, в сравнении
вариантов у такого варианта годовые потери — «—».

## Где VoltPlan отличается от LineCapacity

Отличия ниже не меняют результатов расчёта правильной схемы: на всех
образцах и проверочных схемах числа в окнах и отчётах одинаковы.

| Что | LineCapacity | VoltPlan |
|---|---|---|
| несколько объектов с физически равным наибольшим или наименьшим значением | называет объект, выигравший на ошибках округления | называет первый; число то же (раздел «Равные значения») |
| износ изоляции или температура выходят за пределы вещественных чисел | выводит по сообщению «pow: OVERFLOW error» на каждый получас (до 96 окон), затем те же результаты, что VoltPlan | сразу выводит результаты, `INF` в строках |
| марка со знаком «x» или «х» без сечения («СИП 4х») | сообщение «Ошибка расчёта температуры в ЛЭП №…», у этой и следующих ЛЭП температура 0,0; окно ЛЭП не открывается | отказ в расчёте с понятным сообщением |
| марка, где перед «x» стоит не цифра («СИП-2 Аx50») | дважды сообщение «Некорректное обозначение количества жил в марке провода!», затем те же результаты, что VoltPlan (число жил 0) | расчёт с числом жил 0 без сообщения |
| все нагрузки нулевые | распределение мощности по фазам — шум округления (например, 746,4 %) | распределение 0,0 % по всем фазам |
| cos φ = 0 у индивидуальной нагрузки | расчёт не заканчивается | окно потребителя не принимает, для схемы из файла — отказ в расчёте |
| потребитель или опора, не присоединённые к ЛЭП (только из файла) | — | отказ в расчёте до его начала |
| ЛЭП нулевой длины (только из файла) | сообщение «pow: OVERFLOW error», расчёт не заканчивается | отказ в расчёте с понятным сообщением |
| схема с потребителями, но без ЛЭП (только из файла) | — | отказ в расчёте с понятным сообщением |
| «Основные результаты последнего расчёта» после открытия другой схемы, до её расчёта | отчёт из результатов прежнего расчёта и объектов новой схемы, с бессмысленными числами (`NAN`, `2,3135E242`) | кнопка «Итоги» недоступна до расчёта; после расчёта новой схемы доступна, если уже была доступна в этом сеансе, — как пункт меню LineCapacity |
| импорт из Excel: у потребителя, до которого дошёл поиск, текст дополнительных данных длиннее 21 знака и обрывается раньше запятой | пустое окно ошибки, импорт прерывается на середине: часть потребителей уже получила нагрузки, итогового сообщения нет | отказ «Импорт прерван…» с именем потребителя, схема не меняется |
| распределение по балансному прибору: мощности, записанные в файл | число в 15-й значащей цифре может отличаться на единицу (промежуточные вычисления с повышенной точностью) | запись с двойной точностью; на отчёт и окна не влияет — они совпадают |

## Быстродействие

Связность находится словарями, матрица узловых уравнений собирается и
решается в разреженном виде. Время расчёта обоих сезонов с режимом
минимальных нагрузок, вместе с подготовкой всех строк ответа:

| Схема | Опор | ЛЭП | Потребителей | Время |
|---|---|---|---|---|
| «Ботвиново ГКТП397» | 85 | 167 | 82 | 0,03 с |
| синтетическая | 150 | 450 | 300 | 0,1 с |
| синтетическая `tests/data/calc/крупная-299.cir` — наибольшее допустимое число опор | 299 | 897 | 598 | 0,22 с |

Несвязная схема (потребитель или опора вне ЛЭП) отклоняется до расчёта, поэтому
до вырожденной системы уравнений дело не доходит.
