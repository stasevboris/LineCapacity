# План этапа 2 — расчёт режима

## Цель

Посчитать режим построенной или открытой схемы и показать результаты на схеме
и в окне «Основные результаты». Расчётное ядро разрабатывается для
взаимозаменяемости с LineCapacity: схема, посчитанная у нас и в LineCapacity,
даёт одинаковые результаты.

## Что добавляется

| Часть | Содержание |
|---|---|
| пакет `linecapacity` | расчётное ядро: модель сети, настройки, типовые графики нагрузки, решатель (узловые потенциалы, токи, потери, тепловой расчёт проводов и трансформатора) |
| `voltplan/calc` | мост «единая структура схемы → модель ядра», проверка схемы перед расчётом (сообщения LineCapacity), результаты для схемы и текст «Основных результатов» |
| API | `POST /api/calc` — схема, период (лето, зима, оба), режим минимальных нагрузок → результаты по сезонам и отчёт |
| клиент | кнопка «Расчёт», окно выбора вида расчёта, слой результатов на схеме (напряжения у потребителей, красные при выходе за 198…242 В; температуры проводов; провод с наибольшей температурой; напряжения на шинах ТП; мощности; температуры трансформатора), переключатель «лето / зима / минимальные нагрузки», окно «Основные результаты», результаты в свойствах объекта |

## Порядок работ

1. Расчётное ядро — пакет `linecapacity`: модель сети, узловые уравнения,
   тепловые расчёты проводов и трансформатора; без комментариев, с
   аннотациями, ruff в ноль.
2. Мост и результаты: `to_model`, `check_scheme`, `run(scheme, period,
   min_load)`. Неизвестный тип потребителя (например, 49,894… в образцах)
   даёт потребителя без нагрузки, как в LineCapacity.
3. Маршрут `/api/calc`, проверка входных данных, журнал.
4. Клиент: окно вида расчёта, слой результатов с положениями подписей как на
   схеме LineCapacity, окно отчёта. После любого изменения схемы
   результаты скрываются: в LineCapacity правка тоже сбрасывает их показ.
5. Документы: README (раздел «Состояние»), `docs/04` (маршрут и модули),
   план тестирования (сверка результатов).

## Проверки

- **Модульные.** Ядро на малых схемах с известным ответом: один потребитель,
  однофазный и трёхфазный; ноль нагрузки; неизвестный тип; оба сезона; режим
  минимальных нагрузок. Мост сохраняет все поля.
- **API.** Коды ответов, отказ на несвязной схеме с текстом LineCapacity,
  формат результата.
- **Живые.** Расчёт из интерфейса, переключение сезонов, окно отчёта,
  скриншоты светлой и тёмной темы.
- **Сверка с LineCapacity.**
  - Все 18 образцов и все 8 сценариев из `tests/sequences.py` считаются в
    LineCapacity: F7, «Запустить расчёт», текст окна «Основные результаты
    расчётов».
  - Текст сравнивается с нашим отчётом построчно; числа — с точностью, с
    которой их выводит LineCapacity (0,1 В; 0,01 кВт).
  - Схема, построенная у нас, считается в LineCapacity, и наоборот.
  - «Основные результаты» есть только при двух и более потребителях, поэтому
    сценарии с одним потребителем проверяются по окну объекта.
- **Регрессия этапа 1.** Все проверки этапа 1 остаются в наборе и проходят.
  В общий набор сценариев добавляются ещё два сценария отмены, которые
  дополнительно проверялись на LineCapacity при приёмке этапа 1:
  - «двойная отмена»: отходящая, две отмены подряд, новая отходящая с
    пролётом;
  - «отмена после удаления отходящей»: удаление опоры и отходящей ЛЭП,
    отмена, опора на свободном конце, новая отходящая.

## Чего в этапе 2 нет

Пользователей, проектов, базы данных, настроек типовых нагрузок, сценариев и
вариантов: расчёт идёт по типовым значениям LineCapacity.

## Риски

- Решатель медленный на крупных схемах. Замерить время на «Ботвиново»
  (167 ЛЭП); если дольше 2 с — векторизовать сборку матриц.
- Округление в тексте отчёта. Числа выводить по правилам LineCapacity
  (точность, число знаков после запятой, переход к записи с порядком), а не
  округлением Python.
